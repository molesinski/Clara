# Updating the Embedded Snowball Stemmers

## Source and scope

The 33 algorithms in `src/Clara.Analysis.Snowball/Snowball/Algorithms` use Snowball 3.2.0 from [upstream commit 6389c79](https://github.com/snowballstem/snowball/commit/6389c79f91cd67ed2de3ebdcf84ec8c2d2d23c11). The exact revision is pinned for reproducible generation.

Generation preserves the existing language selection, public analyzers, stopword lists, and namespaces. New upstream languages are not imported automatically.

## Generate with Docker

Requirements: Git, PowerShell, Docker with Linux containers, and the repository's .NET SDK for verification. A local C compiler, Make, and Mono are unnecessary.

Run from the repository root:

```powershell
./tools/Update-Snowball.ps1
dotnet restore Clara.slnx
dotnet build Clara.slnx -c Release --no-restore
dotnet test src/Clara.Tests/Clara.Tests.csproj -c Release --no-build --no-restore
./tools/Verify-Snowball.ps1
```

[`Update-Snowball.ps1`](../tools/Update-Snowball.ps1) fetches the pinned commit into ignored `artifacts/snowball/`, checks that the checkout is clean, and builds `dist_libstemmer_csharp` using the official GCC 14 Bookworm image pinned by digest. The source mount is read-only; compilation runs inside the disposable container without network access. Only the generated output mount is writable. Git downloads and the first Docker image pull require network access.

The script validates all expected source files before writing repository files as UTF-8 with BOM and CRLF. Repeating it with the same inputs produces identical files. Keep the generated-code `.editorconfig` and upstream copyright notices.

## Preserve Clara's allocation optimizations

- Keep runtime and generated algorithm classes internal.
- Retain `Stemmer.SetBufferContents(Token)`: copy directly into the existing `StringBuilder`, then reset all cursor and slice state. Do not convert each input token to a string.
- Keep each language filter's `ObjectPoolSlim<TStemmer>` and copy the result directly from `Buffer` into the writable token. Do not replace this path with `Stem(string)`, `Current`, or `ToString()`.
- Preserve reusable scratch buffers and static `Among` tables generated by upstream. Review future generator changes for allocations moved into per-token methods.

The updater reapplies visibility and the token entry point explicitly. The filter classes remain outside its write scope. Some upstream paths still allocate: Finnish slicing can create strings, and instance callbacks used by `find_among` can allocate delegates before JIT optimization. Pooling is not a guarantee of zero allocations for every language and input.

## Verify against upstream

[`Verify-Snowball.ps1`](../tools/Verify-Snowball.ps1) fetches [snowball-data commit 019921c](https://github.com/snowballstem/snowball-data/commit/019921c3a41c2b70063ee3feb215a00c8e594597) and runs the standalone [verification project](../tools/SnowballVerification/SnowballVerification.csproj). It compiles pristine generated C# beside Clara, then compares every vocabulary entry with both upstream execution and the corpus's expected output. It also exercises Clara's token entry point on the same reused stemmer for inputs within `Token.MaximumLength`. Plain and gzip-compressed vocabularies are streamed. Any mismatch or unequal input/output line count fails the command.

The verifier is separate from the normal solution and tests; normal builds need neither Docker nor downloaded corpora. Corpus files and their licenses remain in the ignored checkout. Analyzer suppression applies to this verifier, which compiles unmodified upstream code; the library and tests retain their normal checks.

Rebuild indexes after changing stemming rules so indexed and queried terms use the same analysis. See [the test map](development-and-testing.md#test-map) for unit coverage and [Benchmarks](development-and-testing.md#snowball-320) for analyzer measurements and commands.

```powershell

./tools/Verify-Snowball.ps1 -SnowballRevision <same-commit> -DataRevision <corpus-commit>
```

Review the generated diff and runtime changes, run all builds/tests and comparable benchmarks, and update this provenance record. After accepting the update, change the default revision/version in the updater, the verifier script's revision defaults, and the verification project's fallback revision. Add public support for new languages as a separate, deliberate change. The scripts prepare local files; they do not commit or publish anything.
